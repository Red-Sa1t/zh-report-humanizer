# AI 写作特征完整清单（中文报告版）

来源与依据：

- Wikipedia [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)（WikiProject AI Cleanup 维护，被媒体评为目前最实用的 AI 写作识别指南之一）
- 中文语体的对应特征由英文清单映射而来，并补充中文特有项

> **前置警告（来自该指南本身）**：不要依赖 AI 检测工具，也不要过度相信自己的判断。指南记录的研究显示，2025 年的实验中人类分辨 LLM 文本的能力**接近随机水平**；重度 LLM 用户的准确率约 90%，也就是说标记 10 篇大约会错 1 篇。**把精力放在内容具体性上，不要放在骗检测器上。**

---

## A. 内容层

### A1 意义拔高（WP:AILEGACY）

给研究对象硬加"更宏大意义"。

- 中文表现：「具有里程碑意义」「标志着…的新篇章」「为…奠定了基础」「推动了…的发展」
- 判据：把这句话删掉，信息量是否为零？为零就删。

### A2 空洞归纳

「综上所述」「总而言之，XX 具有重要意义」：总结段不提供新信息，只重复。

### A3 万能挑战段（WP:FACESCHALLENGES）

结尾固定公式：「尽管…面临挑战…但未来有望…」

- 改法：要么删，要么换成一个**具体的、可验证的**局限（例如"该工具不解析依赖树"）。

### A4 肤浅分析 / 现在分词尾巴（WP:SUPERFICIAL）

英文是句尾 `-ing` 短语（*reflecting*, *underscoring*, *highlighting*），中文对应：

- 「…，体现了…」「…，彰显了…」「…，反映出…」「…，折射出…」
- 改法：删掉，或改成独立句子并**给出证据**。证据比评价有力。

### A5 模糊归因

「专家指出」「业内人士认为」「有研究表明」：没有具体来源。

- 中文报告里尤其常见：「业界普遍认为…」

### A6 宣传腔

「亮眼成绩」「瞩目成就」「欣欣向荣」「表现出色」

## B. 语言层

### B1 AI 高频词

**英文**：delve, crucial, pivotal, robust, landscape, showcase, meticulous,
intricate, interplay, foster, enhance, highlight (v.), garner, enduring,
align with, boasts, testament to, underscore

**中文一级（铁证）**：赋能、助力、深耕、聚焦、打造、引领、抓手、闭环、
多维度、全方位、一站式、沉浸式、底层逻辑、顶层设计、生态位、护城河、
里程碑、新篇章

**中文二级（密集才可疑）**：此外、与此同时、值得注意的是、综上所述、
总而言之、不难看出、显而易见、毋庸置疑、众所周知、由此可见

### B2 回避基础系词

英文 AI 倾向回避 "is/are"。中文对应：该说「是」的地方用「作为」「系」「乃」「属于」。

### B3 否定再肯定 / 否定平行（WP:AIPARALLEL）：**本 skill 列为硬规则一，无例外**

同一个句子里先否定、再补一个肯定：

- 「不是…而是…」「不是…则是…」「不是…是…」
- 「并非…而是…」「并非…，是…」
- 「不仅是 X，更是 Y」「不只是…，更是…」「不仅仅是…还…」
- 「与其说…不如说…」
- 「没有 / 不…，反而 / 恰恰…」（先否定，再反推一个肯定）

制造"纠正读者误解"的假象，实际没有纠正任何人。读者要多读半句才拿到结论。这种句式看着有论证感，实质是语气上的强调。

**改法二选一，禁止两半都写**：

1. 只留否定：「不是配置问题。」「这里没有检出许可证。」
2. 只留肯定（推荐，信息量更大）：「失败的原因是网络在传输大文件时不稳定。」

**检查方法**：搜索「而是」「则是」「更是」，凡是同一句里前面带「不是 / 并非 / 不只 / 不仅」的，删掉一半。原因分析（"失败的原因不是 A，而是 B"）和方案对比（"该工具不是 X，而是 Y"）是重灾区。

### B4 三连排比（WP:RO3）

「高效、稳定、可靠」「形容词+形容词+形容词」

用三连把一个平庸的观察包装得像全面分析。**删到一两个，或换成具体描述。**

### B5 同义替换凑变化

同一事物换不同说法：「该工具…此方案…这一软件…」

人类写报告会**固定术语**，AI 才会不停换词。

### B6 "的"字连珠

修饰链超过 3 个「的」：「基于…的…的…的方法」

### B7 箭头串流程：**本 skill 列为硬规则二，无例外**

用箭头把过程压成符号链：「读取文件 → 解析 AST → 生成报告」「先装依赖 → 再跑脚本 → 最后核对输出」。

问题有两层。第一，箭头省掉的正是环节之间的连接关系，而过程描述里有信息量的部分就是这些连接关系。第二，正文里的箭头含义不唯一，读者要判断它表示先后、映射还是赋值。

**改法**：用关联词把顺序说出来（「从读取文件开始，然后解析 AST，再到生成报告」「先装依赖，再跑脚本，最后核对输出」），环节较短或顺序不重要时直接用顿号并列（「处理流程是读取文件、解析 AST、生成报告」）；确实是操作步骤就用有序列表，不要用箭头串。

**豁免**：代码块和行内代码里的箭头照常写，shell 管道、C 指针、lambda、Makefile 依赖、Mermaid 流程图都在此列。

**检查方法**：搜索 `→` 和 `->`，代码块之外的命中都要改。

### B8 破折号：**本 skill 列为硬规则三**

中文里 `——` 密集出现，绝大多数用于补充说明或制造停顿。

- 「工具只扫描仓库文件——不处理依赖」（补充说明）：改逗号、括号，或拆成两句
- 「具体性——数字、文件名、命令」（解释定义）：改冒号
- 「结果只有一个——全是误报」（停顿强调）：改逗号，或直接写成两句

不要把破折号当逻辑连接词，它不表示因果、转折或递进。写不出连接关系时应该补连接词或拆句。

**例外**：引文里原文带破折号（照引不改）、专有名词或书名本身含破折号、表格里用单个「—」表示空值。

**检查方法**：搜索 `——`，正文里的命中都要改，目标数量为 0。

### B9 流水句与情态词（正向手法的靶子，不是硬规则）

这一类不违反任何硬规则，自检脚本也只把它列成候选。它的特征是四个以上小句靠逗号并排，主干不清，句间关系要读者自己猜；同时「能」「可以」「能够」这类可能性表述密度偏高。

- 反例：「图片压缩与预处理，手机拍的原图一张 3 到 5 MB，压缩到 500 KB 以内再上传，跨网传输量能降一个量级。」
- 改后：「图片压缩与预处理：将手机拍的原图从 3 到 5 MB 压缩到 500 KB 以内再上传，跨网传输量降一个量级。」

三个手法：**降级**（挑一个分句当主干，其余降成状语或定语）、**显性化**（补出「以」「从而」「因为」这类连接词）、**去情态**（删掉「能」「可以」「能够」，改成直陈）。

压缩的是句式，不是信息。过程步骤和具体数字要留住，别为了凑一个单句把它们删掉。

**注意**：中文本来常用流水句，读得顺就不用动。这一条针对的是主干不清、逻辑靠猜的那种，优先在条目和要点里使用。

## C. 结构层

| 特征 | 说明 |
|---|---|
| 总分总 | 开头预告"本文将…"，结尾"综上所述…" |
| 小标题只包含小标题 | 父标题下无正文，只有一个子标题 |
| 加粗滥用 | 正文关键处**全部加粗**，等于没强调 |
| 行内标题式列表 | `**标签**：描述` 连续铺满整段 |
| 列表代替论证 | 本该推理的内容被拆成 bullet |
| 小标题对仗工整 | 三个标题字数结构完全一致 |
| 表格滥用 | 用表格承载本该是散文的对比 |
| 分隔线切段 | 每节之间都插 `---` |
| 层级跳跃 | 从 `##` 直接跳 `####` |

## D. 标点与排版

| 特征 | 说明 |
|---|---|
| 破折号滥用 | 中文里 `——` 密集出现，见 B8（硬规则三） |
| 箭头代替连接词 | 正文里用 `->`、`→` 串流程，见 B7（硬规则二） |
| emoji 打标记 | ✅ ❌ 🚀 💡 ⚠️ 当列表符号或强调，见 SKILL.md 硬规则四 |
| 引号不统一 | 中文正文里直角引号「」、弯引号 “” 和英文直引号 "" 混着用；全文选一种 |
| 中文里夹半角标点 | 「扫描用了123秒,比预期慢」：中文句子里用全角逗号、括号、冒号 |
| 中英文混排空格不统一 | 有的地方「698 个」，有的地方「698个」；全文统一 |
| Markdown 味过重 | 报告里大量 `##`、`**`、`-` 堆叠；交 Word / PDF 时残留 Markdown 符号 |

## E. 人写的正向信号（该指南专门有一节）

| 信号 | 含义 |
|---|---|
| **能解释自己的取舍** | 作者能说清"为什么这么做"，而不只是"做了什么" |
| **与时间相关的具体细节** | 提到具体日期、版本号、commit、报错原文 |
| **承认不确定性** | "这一点我没能确认" |
| **写出排查中的误判** | "我最初认为是 A，改了之后仍然失败，所以是 B" |

**AI 很少说"我不知道"**，它会给一个听起来合理的解释，所以承认不知道是人味信号。

原指南还把「语法不规则（破碎句、插入、自我修正）」列为人写的信号。这一条适用于百科编辑和随笔，**不适用于正式报告**：报告要求语句完整，不要为了显得像人而故意写破碎句。人味靠的是内容层面的真实过程，见上表最后一行。

## F. 无效指标（不要用这些判断）

- AIGC 检测率分数（工具误判率不低）
- 你自己的直觉（人类分辨力接近随机）
- 文本是否"用词高级"（能用词高级的 AI 比比皆是）

## G. 中文报告特有补充

课本/作业语体里额外高频的 AI 腔：

1. **课程套话**：「通过本次实验，我深刻认识到…」，改成具体收获
2. **教科书式定义开头**：「XX 是一种…的技术」，直接进正题，除非题目要求
3. **每节必配"小结"**：只在真的需要收束时写
4. **伪具体**：「大量的文件」「较长的时间」「较高的比例」，这些不是具体，是修饰过的模糊
5. **被动堆砌**：「被检测出来」「被认为」，中文报告该用主动语态

> 第 4 条最容易被忽略：**"大量""较高"看着像量化，实际和"很多"一样空**。只有数字才是具体。

6. **编造参考文献**：题名、作者、期刊看着都像真的，实际查不到。这是 AI 起草报告时后果最严重的问题，比任何文风问题都严重。每一条都要自己查到原文再列。
7. **人称混用**：同一篇里「我」「我们」「笔者」「本文」轮着用，属于 B5 同义替换在人称上的表现。

## H. 图表层

| 特征 | 说明 |
|---|---|
| 彩色圆角框 | 流程图、架构图全是圆角矩形、彩色填充、渐变、阴影，像 PPT 模板 |
| 图标和 emoji 进图 | 节点里放 🚀 📂 🔍 或图标库小图标 |
| 图内大标题 | 图片顶部一个标题，下面又有图题 |
| 图题是评价或结论 | 「高效稳定的系统架构」「线程越多越快」 |
| 只贴图不解读 | 图后没有一句话说明读者该看什么 |
| 正文没引用 | 图表单独出现，正文里找不到「如图 X 所示」 |
| 颜色是唯一区分 | 折线图几条线只靠颜色区分，黑白打印后分不清 |

改法和各工具的黑白直角预设见 [figures-zh.md](figures-zh.md)。
